# Sporer Plan 5 — rulings, parked findings and checks before release

These are the decisions made on the owner's behalf while building Plan 5: the service worker, the signed-out reload, the WebKit smoke set and browser cache in CI, ReadyToRun with a start-up warm-up, the edit bar follow-ups, and the final §8 performance pass. The plan was built task by task, with a separate review of each task, then a whole-branch review and one fix wave. Each decision states what it costs if it turns out wrong.

## Check before the `v1.2.0` tag

The owner's §8 sign-off and the editing checklist in the README are the acceptance test. In short:

- **Install and start.** Add the app to the Home Screen; a start from the Home Screen shows the map within 2 s on the VPN; with the VPN off the app opens with its own error and Retry, not a browser error page.
- **Updates.** After the server runs a new release, the next start of the app runs it; an app left open keeps running until it is closed.
- **Signed out.** When the login in front of the app has expired, the app goes to the login on its next request.
- **Edit mode on the iPhone.** The points draw and can be tapped and removed (the WebKit smoke set in CI does not check this; see P5-R13). With edit mode on and the sheet at its peek, the edit bar's row is fully visible at text size 100 %, 115 % and 125 %, and with Display Zoom set to Larger Text.
- **§8 on the phone.** Day, month and year within 1, 2 and 3 s; pan and zoom smooth on the Year view; no failed Overland uploads while a rebuild runs.

These cannot be verified in the build container (no iPhone, no real network, no real tiles):

- The service worker's behaviour in a Home Screen app on iOS (install, update, a start without a network, the last-resort recovery in the README).
- The login redirect inside a standalone app.
- Real map tiles and the real VPN: the §8 numbers were measured with recorded answers and an emulated network (`2026-10-29-sporer-plan-5-perf.md`).
- Pan and zoom smoothness: SwiftShader draws on the processor, far slower than the iPhone's GPU.
- Upgrading from v1.1.0: no migrations. The first start compiles less (ReadyToRun) and warms the trips code in the background; the first start of the app after the upgrade installs the worker.

## Rulings

- Ruling P5-R1: The version also hashes the content of every precached file outside /assets/ (the public/ files: manifest, icons), not only the names and index.html — else a changed icon or manifest never reaches an installed app. Amends the constraint "a hash of the precached files' names and of index.html" — If wrong: a few bytes more hashing at build.
- Ruling P5-R2: A navigation answer is kept as /index.html only if it is ok, basic, text/html AND its body contains the app's root element (`<div id="root">`), so a same-origin sign-in page that answers 200 never becomes the offline shell — If wrong: one clone and text() per successful navigation.
- Ruling P5-R3: Accept the extras: case- and percent-insensitive /api matching (ASP.NET routes are case-insensitive), keeping a late network answer, ignoreVary on lookups (the API compresses with Vary), hidden files excluded, the base "/" guard, build type-checking src/sw, the check:sw alias, and the separate `build` typecheck project with its own Node declarations (vite.config.ts moves to it) — provided `npm run typecheck` checks every project — If wrong: small revert.
- Ruling P5-R4: Fix on branch claude/sporer-edit-bar-fix (worktree scratchpad/main-wt, from main) by saying the load state in the edit bar's row (and only Done while there are no points), with a toBeInViewport regression check run under the DejaVu override; squash it onto main as its own commit (a fix to a red main, outside Plan 5's squash) and the owner tags v1.1.0 there; then merge main into claude/sporer-pwa — If wrong: main carries two commits for v1.1.0 instead of one.
- Ruling P5-R5: Drop `remember` (and P5-R3's "late network answer still cached"): no navigation answer is ever stored. The offline fallback is only the /index.html precached at install, which must be ok, basic, not redirected, text/html, contain `<div id="root">`, and reference under /assets/ only files in this worker's list (a pure `isAppPage(html, shellFiles)` in shellPolicy, unit-tested); otherwise the install fails and is tried again at the next update check. This supersedes P5-R2 (no navigation answer is kept) and amends the plan's Task 1 Step 2 ("a response that is ok … is put in the cache") — why: the version already hashes index.html, so a page from the same build is identical to the precached one and a page from another build is inconsistent; also covers a deploy switching between fetching sw.js and index.html — If wrong: an offline start shows the shell of the last fully installed version, which is what it should.
- Ruling P5-R6: Accept the other extras (build type-checks src/sw, a check:sw script, isShellDocument). Fix Minors 1 and 2; Minor 3: stop exporting shellFilesOf/versionOf unless a test uses them. P5-R1 hashes each precached file outside /assets/ by its bytes (name and sha256 per file), mirrored in check-sw with a negative test (a changed manifest changes the version).
- Ruling P5-R7: Add Plan 5 Task 6 "Edit bar follow-ups" (after Task 5's server work, before the final §8 pass is fine; any order after Task 2): (a) a later failed load (points still on screen) says its alert in the row in place of the count, keeping Clear/Remove/Done, so it shows at the peek; (b) focus never falls to <body> in edit mode: when a removal stops pending or `selectable` turns false and focus is on body/null, focus goes to Clear if enabled, else Done. Both with unit tests and an e2e viewport/focus check under the DejaVu override — why: the fix review found both (the first is the same hidden-at-peek defect; the second predates it) — If wrong: two small UI changes.
- Ruling P5-R8: A sessionStorage that throws means the signed-out reload does NOT happen (the error with Retry shows, as for a network error): without the 60 s guard a page whose API keeps redirecting would reload without end. Amends the constraint "sessionStorage that throws counts as never reloaded" — If wrong: in a browser with storage disabled, an expired session needs a manual reload.
- Ruling P5-R9: Accept e2e/signed-out.spec.ts as its own file, and the /login stub via context.route; the experimental Playwright env var is acceptable if the reviewer confirms the offline test fails without the worker's cache (mutation) and the variable is scoped to that spec's worker process — If wrong: the offline test is vacuous; revisit when Playwright is upgraded.
- Ruling P5-R10: Split the browser cache into actions/cache/restore + actions/cache/save with `if: always()` (save only on a miss), so the browsers are cached even when the tests fail — If wrong: one more step in the job.
- Ruling P5-R11: A manual run on a branch other than main or a tag BUILDS the image without pushing it (as a pull request does), instead of skipping the build job: the registry login, the push and cosign are skipped. Amends the plan's "runs the test and web jobs only" and Task 3 Step 3's `if:` — why: Task 4 changes the Dockerfile (ReadyToRun), and a skipped build would leave that unverified until main, where a failure is a red main — If wrong: a branch run takes a few minutes longer.
- Ruling P5-R12: Publishing is decided once per run: the build job always runs (P5-R11) and publishes (registry login, push, cosign install and sign) only for a push event, or a manual run on main or on a tag starting `refs/tags/v`; pull requests and every other manual run build without pushing. Write it as one job-level env value (e.g. PUBLISH) used by each step's `if:` and by `push:`. The README says exactly this — If wrong: a manual run on a v-tag that is not a release publishes, as today.
- Ruling P5-R13: The WebKit smoke set leaves out tests that read WebGL pixels or rely on page.route under a controlling worker; those stay on Chromium. Untag the edit-points pixel test and the two service-worker cases; add one service-worker smoke test that runs on every project and needs no API: register /sw.js from a document that is not the app (e.g. /icons/icon.svg, workers allowed), wait for `activated`, and check the cache holds the shell files and /index.html — so WebKit proves sw.js parses and installs in Safari's engine. If no edit-points test works without pixels, removing points on WebKit is left to the owner's iPhone checklist (Task 5 README) — If wrong: a WebKit-only drawing bug in edit mode goes unseen in CI.
