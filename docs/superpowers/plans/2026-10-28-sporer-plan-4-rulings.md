# Sporer Plan 4 — rulings, parked findings and checks before release

These are the decisions made on the owner's behalf while building Plan 4: renaming, merging and separating places, removing and restoring points, trip edits, the home override, the trip distance and the Settings page. The plan was built task by task, with a separate review of each task, then a whole-branch review and one fix wave. Each decision states what it costs if it turns out wrong.

## Check before the `v1.1.0` tag

The owner's editing checklist in the README is the acceptance test. In short:

- **Places.** Rename a place, then merge two places, one of them home. The names show in the day, the range, the place view and a trip day's highlights. Separate undoes a merge.
- **Points.** Remove a GPS spike in edit mode and undo it from the toast. Remove it again and leave it; restore it later from Settings › Removed points.
- **Trips.** Rename a trip and change its dates, then delete one and restore it from Settings › Deleted trips.
- **Home.** Set a home for a period in Settings › Home, and see the trips follow at once.
- **Trip distance.** Change it in Settings › Trips. The list changes without a rebuild of the timeline.

These cannot be verified in the build container (no WebKit, no real phone, no real data):

- Edit mode on the iPhone: tapping a point and dragging a box with a finger, and the native date pickers of the trip form.
- How long edit mode takes to draw a dense day on the phone. The 4× throttle used in the perf check does not reach MapLibre's worker, so the phone will be slower than the 1.0 s measured (see `2026-10-28-sporer-plan-4-perf.md`).
- Toasts and the Settings page clear the home indicator and the Dynamic Island.
- Upgrading from v1.0.x applies migration `0006_edits.sql` (new tables and two nullable `trip` columns) and rebuilds nothing: the algorithm version does not change.

## Notes for Plan 5

- **The first edit after a process start** takes 232–259 ms (JIT), under the 300 ms target but far from the steady 20–50 ms. ReadyToRun, or a read-only warm-up, should remove it (P3-R26 is the same cause).
- **Edit mode on a dense day** was timed before its halo became a layer of its own (P4-R45). Measure it again in the final pass.
- **Trip dates, applied or stored.** `startEdited` and `endEdited` say an edit has a date stored, not that it was applied. A date set from another device while the form is open can be taken back by an untouched save (Task 9, parked). Telling them apart needs the server to report both.
- **Place search** reads `segment` twice: about 6 ms at 10.7 M rows, the one new query whose cost grows with the history. Watch it.
- **`RenameMergeTests`** (about 1 600 lines) could be split by endpoint if it keeps growing.
- **The service worker, a WebKit smoke project in CI, CI browser caching, Plan 1's `day-latency.sh` seed, and the final §8 pass,** as planned.
